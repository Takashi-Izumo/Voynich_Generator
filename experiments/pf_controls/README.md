# PF capability replay controls

Implements the [report 016 contract](../../sandbox/m1-review/reports/016-controls-and-main-comparison-20261105/CONTROL_CONTRACT.json) in a separate package, calling the literal original BASE generator. The PF candidate surface-commit repair in [implementation 020](../../sandbox/m1-review/implementation/020-pf-surface-commit-fix/VALIDATION.md) is separate from this replay. This package is not imported by the production generator. A smoke is a mechanism check, not capability evidence.

Report019 independently completed all106 controls and 2,240 replay branches; capability was not verified. The `verify-export --exported ...` CLI dispatch is fixed in implementation020 and exercised against fresh, audited artifacts. Historical results and model-set remain unchanged; the future measurement/control design is [proposal021](../../sandbox/m1-review/designs/021-pf-measurement-controls-v2/DESIGN.md).

The literal original `generate_bif` is observed at its first `complete_segment` call for each PF event. Candidate zero carries an exact clone of the main entry RNG. The full GenerationState, sampler instance controls and inherited effective class configuration (including paragraph-H1 baseline), legacy numbering, immutable-table fingerprints, fold/known3/layout are saved. Each event is replayed on 64 private state/sampler clones using `PF_CAPABILITY_REPLAY_20261105_V1`, seed 92101, event and branch IDs. The private clones retain the entry request number; they never advance the production counter. Production's two candidates and LEN1 run unchanged after observation. Bindings and class configuration restore in `finally`, removing new overrides and restoring mutable values, and every observed page must match an ordinary original page in all semantic outputs, full final state and actual main RNG.

Persisted snapshots are inspectable JSON, not executable object serialization. Replay reconstructs entry states by re-running the literal BASE trajectory. Audit does the same from source, compares the entire freshly computed record, and checks cheap structural coverage first. It never trusts supplied state hashes as a substitute for replay. This deliberately costs another generation/replay pass. Correction probability caches are shared read-only in meaning; private audit/counter/log collections are copied. Their content fingerprints and ordinary BASE equivalence are checked.

The new tables use external16 complete bifolia, all four faces, strict segments. PF distributions shrink to ordinary nonfinal LF endpoints (joint length/visible width and terminal) or interior BODY transitions (SPACE), mass 20. Ordinary priors use mass 0.5; absent BODY contexts back off to its marginal H1 distribution. Counts give every contributing leaf equal weight, rescaled to the observed event count. Source membership, all count arrays, backoff contexts and table hashes are in the plan.

Selectors receive only generated BASE anchors, replay donors and external tables. Joint length bins are <=3 / 4–6 / >=7; visible-width bins <=3 / 4–6 / 7–9 / >=10. Visible glyphs/WIDTH use the frozen judge tokenizer; physical endpoint width is separately recorded. Terminal filters fix BASE length bin, exact visible/physical widths and NMY/LR/OTHER family. SPACE fixes those widths, length bin and exact terminal, and requires a predecessor within the donor segment. Near/far minimize/maximize strict proxy NLL relative to BASE, epsilon 1e-12, first branch ID on ties. Missing matches remain `NO_MATCH_WITHIN_64` without new seeds, relaxed filters or extra draws.

Structural FULL PF eligibility is fixed before selection/prediction. Only after selection is sealed and audited are entire selected donor segments substituted into genuine pages. END_ONLY/NONE, other segments, masks, layout and known3 stay as observed. Every eligible leaf has one page variant per family/direction, including unchanged variants. All channel feature changes and selection failures are reported. Target-channel manipulation means the genuine and modified page's empirical target feature counts differ; it is measured after sealing and never feeds selection. A/B truth is the unchanged genuine page, assigned by a deterministic hash independent of NLL/CAL. Near is diagnostic. Three far channels gate separately under report 016; CAL is two-sided null typicality.

## Reproduction

Use the repository's configured Python environment with its existing numpy/pandas/scipy/numba dependencies and trusted parent archives. In this cloud the interpreter is `/workspace/.venvs/voynich/bin/python`; set `NUMBA_NUM_THREADS=2` and `PYTHONPYCACHEPREFIX=/workspace/voynich-setup/pycache`. Replace `python` below with that interpreter. Each output path must be new, outside the generated artifact directory. Example scratch root: `/workspace/voynich-results/pf-controls-independent-20261105`.

```bash
python -m experiments.pf_controls plan --output /workspace/voynich-results/pf-controls-independent-20261105/smoke-plan
python -m experiments.pf_controls generate --plan /workspace/voynich-results/pf-controls-independent-20261105/smoke-plan/plan.json --output /workspace/voynich-results/pf-controls-independent-20261105/smoke-generated
python -m experiments.pf_controls audit --plan /workspace/voynich-results/pf-controls-independent-20261105/smoke-plan/plan.json --generated /workspace/voynich-results/pf-controls-independent-20261105/smoke-generated --output /workspace/voynich-results/pf-controls-independent-20261105/smoke-audit
python -m experiments.pf_controls export --plan /workspace/voynich-results/pf-controls-independent-20261105/smoke-plan/plan.json --generated /workspace/voynich-results/pf-controls-independent-20261105/smoke-generated --output /workspace/voynich-results/pf-controls-independent-20261105/smoke-export
python -m experiments.pf_controls verify-export --plan /workspace/voynich-results/pf-controls-independent-20261105/smoke-plan/plan.json --generated /workspace/voynich-results/pf-controls-independent-20261105/smoke-generated --exported /workspace/voynich-results/pf-controls-independent-20261105/smoke-export
python -m experiments.pf_controls.tests.run_probes --plan /workspace/voynich-results/pf-controls-independent-20261105/smoke-plan/plan.json --generated /workspace/voynich-results/pf-controls-independent-20261105/smoke-generated --output /workspace/voynich-results/pf-controls-independent-20261105/probes
python -m unittest discover -s experiments/pf_controls/tests -v
```

Full controls use `plan --bifolia all --kind controls`, then the same generate/audit/export/verify-export commands on fresh paths. `evaluate --plan ... --generated ... --exported ... --models ... --output ... --jobs 1` verifies fixed model/extractor/protocol hashes and all export assignments. The frozen predictor receives only each schema-validated input file. All six groups' predictions are sealed before keyed scoring starts. Per-channel CAL facts and standard all-panel/atom reports remain available. The package writes `CAPABILITY_RESULTS.json`, not an independent `CAPABILITY_REVIEW.json`, and never starts the 800-page orchestrator.

The generated/export roots contain genuine text, snapshots and answer keys; keep them out of Git. Share plans, code manifests and aggregate checks only. The independent cloud owns full controls, capability review and subsequent comparison execution.
