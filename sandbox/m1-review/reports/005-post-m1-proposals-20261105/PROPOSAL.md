# M1本比較後の本体改善案

作成: 2026-11-05（日本時間）。対象は現行v22.3を保存した独立候補。今回は提案までで、新候補の実装・生成・採点は行っていない。

## 結論

**第1案は、段落末専用の語長・幅の生成分布を導入すること。** 第2案はPFスコアの個々の末字成分だけの調整、第3案はPFへのSPACE接続の条件付き補正。初回は混ぜず、1案ずつ比較する。

M1の単純な救済停止・候補0固定では段落末が73.33%から71.94%へ小さく動いた一方、総合・PROTO・W2に一貫した改善がなかった。BASEを対照として保持する。

## 1. 追加診断で分かったこと

凍結審判と同じFULL行・可視stable22条件（mを保持、複合glyphを1glyphと数える）を使った、既存本比較資料の探索的集計。まず各面内で平均し、seedをbifolium内で平均、その後bifoliumを等重みにした。

真正側は**18 target面・29個の可視PF末尾**。seedを変えても真正面の独立標本数は増えない。以下の値をそのまま次モデルの目標確率に固定してはいけない。次の法則は外側評価bifoliaを除いた訓練資料から作る。

| 可視段落末の特徴 | 真正面 | BASE | 救済停止 | 候補0固定 |
|---|---:|---:|---:|---:|
| 長さ1〜3glyph | 27.78% | 19.44% | 25.00% | 44.35% |
| 長さ4〜6glyph | 48.15% | 75.83% | 70.00% | 50.83% |
| 長さ7glyph以上 | 24.07% | 4.72% | 5.00% | 4.81% |
| 平均glyph長 | 4.90 | 4.66 | 4.35 | 3.88 |
| 平均の可視glyph換算幅 | 5.98 | 5.60 | 5.56 | 4.96 |
| 可視glyph換算幅7以上 | 49.07% | 28.98% | 31.11% | 24.63% |
| 末字n | 31.48% | 48.89% | 40.09% | 25.74% |
| 末字y | 40.74% | 27.59% | 38.70% | 36.57% |

BASEは4〜6glyphへ集中し、短い語と長い語の両端が少ない。救済停止は短語側を変えるが、長語側はほぼ変わらない。候補0固定は短語を増やし、平均長・幅をさらに小さくする。

BASEの可視PF290イベント（29箇所×10seed）で、初期2候補を等重みにした長語の発生率は4.49%、初期2候補のどちらかに長語があるイベントは8.98%、選択後は4.72%だった。これは、**選択だけでなく候補生成側の長語不足を調べる根拠**になる。候補群は完全な独立同分布標本ではなく、これだけで原因を確定しない。

現LEN1はstable長5以下の基準語に対してちょうど+1のstable長を認める仕組み。stable長7以上の語を作る救済ではない。可視mによる長さ跨ぎは別に記録し、「常に可視7以上が不可能」とは言わない。

個別CAL channelのBASE正答率は語長・幅61.94%、SPACEの前語末字→PF語頭61.76%、末字58.61%。これらは重複する診断であり、独立した票や有意差としては扱わない。

## 2. 第1案: PF専用の語長・幅分布

### 修正内容

段落末の最後の語について、**短語・中語・長語を含む分布と、残り幅の配分を学習する**。平均を一律に伸ばす補正にはしない。

- 対象は既存`is_pf`に相当する、複数行段落の最終LINE_END segment。植物前segmentや厳密F1LFを混ぜない。
- 外部の真正PF資料から、segment容量・残り幅に条件付けた粗い`P(L, W | PF, capacity)`とclosing gateを推定し、現行の通常行末分布へ縮約する。まず1〜3/4〜6/7+等の少数区分から始め、22glyphの巨大な条件表を作らない。
- PFを閉じるタイミングを大きい残り幅でも選べるか、十分な幅があるときに7glyph以上を親grammarの支持内で生成できるかを分けて設計する。
- 実装方法の候補は、末尾幅を先に確保する方式、またはPF専用gateと残り幅条件付きend語長法則。**gateだけを変える群**と、**PF語長法則も変える群**を分け、どちらが不足を解消したか確認できる設計を求める。
- packing・文法支持・末字整合・rare予算を維持する。合法な長語がない条件では親へbackoffし、その件数を記録する。
- 幅学習には生成器と同じ物理幅profileを使う。上表の可視glyph換算幅を物理幅と同一視しない。m/rare処理を経た最終可視分布も別に監査する。

### 最小の比較

BASE / PF専用gate / PF専用gate＋end語長法則。PF selector・LEN1・末字補正・route等はまずBASEのままとし、短語側への影響も監視する。残差がselector側に移った場合に、別の要因比較を設計する。

### 成功の見方

候補bankと最終可視出力の両方で短・中・長語の分布を確認する。7+だけを増やして短語やW2を悪化させた候補を採用しない。J24.CALと段落末CALの50%からの距離、PROTO、周辺atom、支持・packingを併記する。

訓練と縮約強度の選択は外側評価bifoliaを除く資料で行う。上表の24.07%を目標値として埋め込まない。

## 3. 第2案: PFスコアの個々の末字成分だけを調整

### 修正内容

PF selectorの特徴は幅・幅帯・幅/容量、末字`E=g`、末字族`EF=family`。成分を分け、例えば次で比較する。

```text
S_new = S_BASE + (lambda_E - 1) * S_exact_terminal
lambda_E = 1.0（BASE）, 0.5, 0.0
```

- 幅成分・NMY/LR/OTHERの族成分・LEN1・2候補bankは維持し、個々の末字への加点/減点だけを動かす。
- 元のinterceptも保持し、`lambda_E=1`では元score・生成・RNGの再現を確認する。
- スコア全体を0.5倍してもargmaxは変わらないため、そのような弱化実験は行わない。
- n過多・y不足の原因が個別末字成分にあるかは未確定。上記は成分の寄与を調べる仮説であり、n→yの後処理や固定確率への強制置換は提案しない。
- selectorは現在pre-mの`stable_surface`を用いる。可視n/y/mと内部表記を混同せず、再学習する場合は真正・疑似・適用時の特徴表記を揃える案を**別要因**として設計する。PF以外のm処理を変えない。

### 最小の比較

BASE / `lambda_E=0.5` / `lambda_E=0.0`。第1案と同時に変更しない。PFのn/y/m、短・中・長語、幅、末字族を出し、n/yが動いただけで改善としない。

この案は実装範囲が小さい診断候補。候補bankにない長語を増やす方法ではないため、第1案の代わりにはならない。

## 4. 第3案: PFへのSPACE接続を条件に加える

現PF selectorは最後の語を中心に評価する。直前語とPF語の組について、粗い条件付きの真正分布を追加する案を後続とする。

- `前語末字族 → PF語頭`、`前語長とPF語長の配分`を、外部資料のbackoff付きで扱う。
- まず既存の完全なPF候補segmentに接続scoreを加える案を設計する。最終CSVの語や末字だけを書き換えない。
- 一語segmentでは直前語を作らず、PLANTや行を跨いだSPACEを捏造しない。
- 既存BODYのSPACE分布をpriorとし、PF専用の条件が外部LOBOで予測性を持つか確認する。支持が少なければ親へbackoffする。
- 第1案で幅配分が変わると接続も変わるため、独立した群で寄与を確認する。

## 5. 検証側からの共通要件

1. BASEを保存し、新しい独立overlay/runnerで実装する。植物前はいったん切る仕様を維持する。
2. まず提案1の設計を優先する。提案2は小さな成分比較として別に扱い、三案を一括で変更しない。
3. 末尾の長さ/幅、末字、SPACE接続を寄せる/離す対照で、PF審判が何を検出できるか確認する。生の分布残差も併記し、審判の率だけへ適合させない。
4. 因果解釈が必要ならSHADOWを検証補助として設計する。探索・採番を維持して救済を採用しない対照であり、それ自体を本体改善とは数えない。
5. 現20葉は開発資料の再利用。次のパラメータ選択を同じ評価面の正解に合わせず、外側保持と縮約を使い、独立確認と呼ばない。
6. 新案の適用位置、支持・packing、最終可視表記とstate/RNGのcommitを小規模に確認してから本比較へ進む。現行v22.3・審判・過去の結果を上書きしない。
